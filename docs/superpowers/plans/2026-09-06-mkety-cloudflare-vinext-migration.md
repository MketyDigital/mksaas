# Mkety Cloudflare vinext Migration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the failing OpenNext deployment adapter with Cloudflare's current vinext Workers path while preserving Mkety's existing Next.js 16 application, Auth.js, tenant routing, and runtime behavior.

**Architecture:** Keep the existing Next.js source framework and native `next dev` / `next build` workflow. Add vinext as a parallel Cloudflare build target, generated from the current `vinext init --platform=cloudflare` behavior, and remove OpenNext-only deployment wiring once compatibility is proven. Cloudflare production builds must consume a committed lockfile and non-interactive repository configuration.

**Tech Stack:** Next.js 16.2.4, React 19, Auth.js / next-auth 5 beta, vinext, Vite 8, Cloudflare Workers, Wrangler, pnpm 10.28.1, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-09-06-mkety-cloudflare-vinext-migration-design.md`

## Global Constraints

- Do not downgrade Next.js.
- Do not replace Auth.js in this migration.
- Do not change tenant isolation, custom-domain routing, Automation, Agent, Deploy, Domain, Trading, database schema, or application URLs.
- Keep `src/proxy.ts` authoritative unless the vinext compatibility report proves a narrowly scoped adaptation is required.
- Preserve native Next.js development and build commands alongside vinext.
- Commit no secrets; Cloudflare build/runtime variables remain dashboard-managed.
- Do not merge into `main` until native CI and vinext build checks are green.
- Do not attach or change `mkety.com` during this migration.

### Task 2: Generate the vinext Cloudflare configuration from the current toolchain

**Files:**
- Modify: `package.json`

- Modify: `wrangler.jsonc`

**Interfaces:**
- Consumes: successful Task 1 compatibility result.
- Produces: committed vinext/Vite/Workers configuration generated by the current initializer.

- [ ] **Step 1: Run the official non-interactive initializer in the branch workflow**

After `vinext check` passes, run:

```bash
pnpm dlx vinext@latest init --platform=cloudflare
```

Do not use `--skip-check` for the first initialization run.

- [ ] **Step 2: Inspect generated changes before committing**

Verify the initializer does not modify application source files, `next.config.*`, or tenant/auth logic. Expected generated changes are limited to deployment/tooling files and package metadata.

- [ ] **Step 3: Preserve native Next.js scripts explicitly**

Ensure `package.json` retains:

```json
{
  "scripts": {
    "dev": "next dev",
    "build:next": "NODE_ENV=production next build",
    "dev:vinext": "vinext dev --port 3001",
    "build:vinext": "vinext build"
  }
}
```

Keep existing non-deployment scripts unchanged. If `vinext init` generates namespaced scripts, prefer its generated Cloudflare deploy/start commands rather than inventing replacements.

- [ ] **Step 4: Set Cloudflare production build command through the repository `build` script**

Set:

```json
{
  "scripts": {
    "build": "vinext build"
  }
}
```

so the existing Cloudflare dashboard Build command `pnpm run build` produces the Workers artifact. Native CI must call `pnpm run build:next` explicitly where native Next.js validation is required.

- [ ] **Step 5: Remove OpenNext-only wiring**

Remove:

```text
@opennextjs/cloudflare
open-next.config.ts
.open-next output references
OpenNext-specific preview/deploy scripts
```

Retain Wrangler settings only where they are valid for vinext output. Preserve `keep_vars` behavior if the generated/current Wrangler schema supports it; otherwise rely on Cloudflare dashboard-managed variables without committing values.

- [ ] **Step 6: Commit generated configuration and lockfile together**

```bash
git add package.json pnpm-lock.yaml vite.config.ts wrangler.jsonc .gitignore open-next.config.ts
git commit -m "build: migrate Cloudflare deployment to vinext"
```
